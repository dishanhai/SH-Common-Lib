# SHCLIB 可视化配方编辑器与生成器

状态：用户已确认首版包含原版配方、KJS 内容和 JSON／Java 导出。实现及安装说明以 [配方编辑器说明](../../RECIPE_EDITOR.md) 为准。

## 用户确认范围

首版提供有序／无序合成、熔炉、高炉、烟熏炉、营火、切石、锻造转换、锻造纹饰、药水酿造及药水瓶型转换。支持三个项目目标版本：Forge 1.20.1、NeoForge 1.21.1、NeoForge 26.1.2。

JSON 可从剪贴板导入为画布。包含模型无法表示的字段时，保留原始内容为自定义 JSON；该模式也允许使用目标模组已注册的配方序列化器并导出 KubeJS event.custom 脚本。此版本不反向解析或执行任意 JavaScript，也不添加 GTCEu 硬依赖。

提供配方 JSON、KubeJS 脚本和可编译 Java 资源生成器。Java 为写出配方资源的 save(Path) 工具，使用每个配方唯一的类名；普通配方需要把资源加入数据包或模组资源，工具不自动安装数据包。

## 模块边界

- ULK：`api.ulk.recipe` 的不可变文档、结构校验、版本生成、JSON 导入和安全工作区；不依赖客户端 Screen。
- ULK 客户端：`api.client.ulk.RecipeRegistryValidation` 查询物品、标签、药水及 26 端动态纹饰注册表。
- UUK：通用素材槽、可取消拖放状态、多行代码编辑器和跨版本工作台组合 API。
- SHCLIB 页面：组合上述服务，处理当前草稿、历史、保存保护、预览、复制及导出。
- 加载器桥：读取 SHCLIB 专用酿造配置并使用各端真实酿造 API 注册。药水转换保留瓶型，瓶型转换保留 NBT／组件。

依赖方向保持 SHCLIB → SHBUI。消费方 JAR 不复制或打包 UUK 类。旧 SHBUI 缺少能力时，入口给出更新提示。

## 页面与交互

F10 主控中心 → 设置 → 开发者 → 配方编辑器。宽窗口同时展示画布、属性和输出，窄窗口使用三个页签。320×180 逻辑尺寸下使用横向产物槽、紧凑数值行和三列类型选择。

点击选料、右键／Delete 清空、合成槽间拖动交换；提供键盘槽位导航、撤销和重做。切换类型先确认并允许撤销。子页面有可见返回入口。

未解析数值属于未保存修改。返回时提供保存、继续与放弃；新建、导入或加载替换当前文档前保护未保存修改。另存为已有草稿 ID 和覆盖导出文件需要确认。

错误显示字段及本地化原因。当前文档无效时禁止复制和导出旧结果。生成预览有分页，完整内容通过复制或导出获得。自定义 JSON 使用 UUK 多行编辑，超出大小限制明确拒绝。

## 生成和持久化

工作区为 `config/sh_common_lib/recipe_editor/`。草稿有独立 schema 版本，不能与游戏配方 JSON 混用。导出路径限制在根目录内，UTF-8 写盘采用临时文件后移动，失败保留原文件。

普通配方按实际目标版本的原料／产物结构及 recipes/recipe 目录生成。KubeJS 普通脚本放 server_scripts，酿造配置脚本放 startup_scripts。

酿造不伪装为普通原版 JSON：独立的 brewing/ 配置由服务器启动时读取。远程服务器需在服务器侧复制或生成。相同原版输入和原料遵循原版优先，不承诺覆盖原版酿造。

## 验证契约

核心测试覆盖三端输出格式、多个生成 Java 同次编译及执行、JSON 导入保真、工作区路径边界、损坏酿造配置隔离和默认格式兼容。UUK 验证拖放、取消、键盘及代码文本值。三个 SHCLIB 与 SHBUI 构建分别验证，不以一个端构建代表其他端。

游戏内交互、旁白、GUI 缩放、实际 KubeJS 与数据包加载及单人／独立服务器酿造验收单独记录在项目 TODO.md。构建通过不能替代这些验收。
